# RigidForge — Validated Software Stack

Status: validated 2026-11-15 against PyPI metadata and public docs. Supersedes the stack in the original Gemini chat ("Python URDF GUI Stack Selection"). Items marked **(verify)** were not confirmed against primary sources and should be checked at implementation time.

## 1. Verdict

The architecture holds up: Python + PySide6 + PyVista/VTK viewport, OpenCascade (OCP) for B-Rep, trimesh for meshes, an internal model with pure-function exporters. Eight claims in the original chat were wrong or risky and are corrected below. The most important are the SDF binding, the inertia unit-scaling formula, and the "DAG" model.

## 2. Decisions

- **Direct generation.** URDF, MJCF, SDF and USD are each generated directly from the internal model. No format is derived by converting another (decided 2026-11-15).
- **Persistence.** One person resuming work over days. Project directory with a JSON model file (section 7).
- **Concurrent or collaborative editing is not in scope.**
- **Xacro import is in scope** (section 5, "URDF / xacro import").
- **USD exporter target is the latest Isaac Sim release** (section 5, "USD"). Pin the exact version at implementation time.
- **CAD assets are copied into the project**, and re-importing a changed CAD object is a required feature (section 7).

## 3. Corrections to the original chat

| # | Original claim | Finding | Fix |
|---|---|---|---|
| 1 | `sdformat` Python bindings for URDF→SDF | The PyPI package `sdformat` is an unrelated 2019 GPLv3 project. Official bindings (`sdformat14` etc.) ship with libsdformat via apt/conda, not as a PyPI wheel. URDF→SDF is done by the `gz sdf` CLI. | Generate SDF directly from the internal model. Optionally validate with `gz sdf -k` if Gazebo tools are installed. `python-sdformat` (BSD-2, v0.4.0) or `rod` are pure-Python helpers if a typed SDF layer is wanted. |

| 4 | Robot as a DAG | URDF is a tree (one parent per link). Closed loops are not representable. SDF and MJCF can express loops. | Model a tree plus optional loop-closure constraints. Validate: single root, no cycles, unique names. |
| 5 | `pyqtSignal` in QThread guidance | PySide6 uses `Signal`. | Use `Signal` / `Slot`. |
| 6 | `cadquery-ocp` wheels are ~500 MB+ | Current wheels are at most ~68 MB. | Not a real concern. |
| 7 | usd-core + Qt will fight over OpenGL/TBB | Likely overstated: the `usd-core` wheel is the core libraries without the imaging/Hydra viewer stack **(verify)**. | Keep USD export in its own module and test it in CI; no special isolation needed beyond that. |
| 8 | `yourdfpy` loads Xacro | It does not expand xacro. Xacro is a separate preprocessor (`xacro` on PyPI, 2.1.1). Features like `$(find pkg)` need ROS package paths. | See "URDF / xacro import" in section 5. |

**URDF / xacro import (in scope).** Proposed semantics, to confirm: import is one-way. Run `xacro` to expand to URDF, parse the URDF into the internal model, and resolve `package://` and `file://` mesh URIs, copying the meshes into `assets/`. The model does not round-trip back to xacro. Keep the original xacro and its expanded URDF in the project as import provenance. Expose user-supplied xacro args and package search paths in the import dialog, because `$(find pkg)` and `xacro.load_yaml()` need files on disk and a package path. Fail with a clear message when they cannot be resolved. Imported URDFs often have joint and inertial data with no CAD source, so those links get meshes only, with manual mass and inertia and the source marked "imported".

**USD target: latest Isaac Sim.** As of 2026-11-15, Isaac Sim 6.x docs are published up to 6.2.0, and 6.0.0 moved to Kit 110 and Python 3.12. Sources report that 6.0 introduced "Asset Structure 3.0": USDC for geometry, with materials, instances, base and physics in separate USDA layers, and separate MuJoCo and PhysX definitions for tuning values. 6.x also supports multiple physics backends (PhysX and Newton). Design the USD exporter to emit the layered structure (geometry layer plus physics layer, with physics tuning kept in the `extensions.usd` block). Pin the target Isaac Sim version in `pyproject.toml` or a constants file and test exported assets by opening them in that version **(verify the exact GA version and layer conventions when implementing)**.

## 6. Design points the original chat missed

1. **Face-to-B-Rep mapping for picking.** VTK picks triangles, not B-Rep faces. Tessellate per face (`BRepMesh_IncrementalMesh`) and store a `face_id` cell-data array on the mesh. A pick then maps to a `TopoDS_Face`, and `BRepAdaptor_Surface` can return the cylinder axis or plane normal for joint snapping.
2. **Threading.** Run STEP load, tessellation and coacd off the UI thread. `TopoDS_Shape` is not picklable, so pass BREP bytes (`BRepTools.Write_s`) to a process pool and return numpy arrays plus mass properties. Only VTK/Qt calls run on the main thread.
3. **Units and mass provenance.** Store per part: unit-normalised geometry (m), mass source (explicit mass or density × volume), and the inertia method (B-Rep exact or mesh). Surface the source in the UI.
4. **Inertia validation.** For each link: mass > 0, tensor symmetric and positive definite, principal moments satisfy the triangle inequality (Ixx + Iyy ≥ Izz and permutations), meshes watertight. Warn on extreme aspect ratios of principal moments.
5. **Package layout.** Avoid a subpackage named `io` (confusing next to stdlib). Suggested: `core/` (model, validation), `importers/` (STEP, mesh, URDF/xacro), `physics/`, `ui/`, `viewport/`, `exporters/`, `tests/`. Exporters are pure functions `RobotModel -> files`.
6. **Test oracles.** Compare computed inertia against analytic box, cylinder and sphere. Round-trip exports: load MJCF in MuJoCo, load URDF in yourdfpy, open USD with `Usd.Stage.Open`, run `gz sdf -k` where available.

### Spike findings (2026-11-15)

Run with cadquery-ocp 8.0.1.1.0 (since replaced by cadquery-ocp-novtk 8.0.1.1.0, the same OCP build without the VTK pin), trimesh 5.2.1, mujoco 4.0.1, yourdfpy 0.0.60 on Python 3.13, against `tests/data/hexapod-leg`.

1. **STEP units.** `xstep.cascade.unit` is empty until the STEP controller is initialised. `Interface_Static.SetCVal_s` called before that returns `False` and is ignored silently, and the file then reads in mm. Call `STEPControl_Controller.Init_s()`, then set `"M"`, check the return value, and assert the result (for example by bounding box) in each worker process, because the setting is process-global. Volumes scale exactly (4475.23 mm³ to 4.47523e-6 m³). `STEPCAFControl_Reader` keeps names, colours, nested sub-assemblies and instance references (the XL330 body: 10 products, 4 screw instances, 2 connector sub-assemblies).
2. **OCP 8 API differences.** Label sequences are `OCP.collections.Sequence_TDF_Label` (no `TDF_LabelSequence`). `TopoDS.Face` has no `_s` suffix. `Bnd_Box.Get()` is unbound; use `CornerMin`/`CornerMax`. `BRepBndLib.Add_s` is loose on curved geometry (1.5 mm over on a 33 mm frame); use `AddOptimal_s` for change reports.
3. **Mirroring.** Mirroring a B-Rep with `gp_Trsf.SetMirror` plus `BRepBuilderAPI_Transform(copy=True)` gives positive volume, CoM equal to the reflected CoM, and inertia equal to R·I·Rᵀ, with a watertight, consistently wound tessellation. Bake mirrors into geometry at import; never use negative mesh scale.
4. **Inertia accuracy.** B-Rep `GProp` matches analytic box, cylinder, sphere and box-with-hole to 1e-15. (OCCT's default integration; on freeform CAD surfaces it is only good to about 1e-5, so the implementation uses adaptive integration, see "B-Rep mass properties" in section 7.) Mesh inertia from tessellation is off by about 1e-3 on curved surfaces (sphere 1e-2 at default settings, dominated by angular deflection, not linear deflection). Use B-Rep mass properties whenever a B-Rep exists; mesh-only inputs (STL, OBJ, DAE, 3MF) get mesh inertia with that error. On the hexapod frames, mesh and B-Rep agree to 3e-4. Naively concatenated per-face triangulations of a sphere were not watertight (seam and pole vertices), so the importer must weld vertices with a tolerance before the watertight check.
5. **Non-uniform density (3D printing).** A printed part is not uniform (solid walls, sparse infill), and the model treats it as uniform. A measured mass sets an effective density for the part: mass = measured, inertia = (measured / volume) × unit-density inertia, CoM from geometry. Example: the coxa frame as solid PETG (1270 kg/m³) is 5.68 g. This is an approximation; the error is not quantified.
6. **URDF vs MJCF.** A 3-joint leg written in both formats gives identical FK at 200 random poses (6.9e-17 m). `MjSpec.from_string(...).compile()` and `MjModel.from_xml_string` give the same model. Pitfalls confirmed: MJCF `fullinertia` order is `ixx iyy izz ixy ixz iyz` while URDF is `ixx ixy ixz iyy iyz izz`; MJCF quaternions are scalar-first; MuJoCo diagonalises inertia into `body_inertia` plus `body_iquat`; MuJoCo rejects inertia that violates the triangle inequality (suggesting `balanceinertia`), so RigidForge must validate before export rather than rely on that flag. Position actuators with `forcerange` compile as expected.
7. **STEP writing (task 5 fixtures, 2026-11-16).** `STEPCAFControl_Writer` with name and colour modes writes product names, instance names (`NEXT_ASSEMBLY_USAGE_OCCURRENCE`), nested sub-assemblies and shared products for repeated parts, and `write.step.unit` (`MM` or `M`) sets the file unit; both read back to the same SI geometry. Colours set as linear RGB (`Quantity_TOC_RGB`) are stored as sRGB in the file and read back as linear RGB (float32 precision). Output is **not byte-reproducible**: occurrence ids come from a process-global counter and colour styles are emitted in a pointer-dependent order. Tests must compare STEP content, not bytes; byte-identity applies to RigidForge's own exports only. The fixture generator is `rigidforge.testing.step_fixtures` (fixtures `two_link_arm` and `gripper_arm`, generated at test time, not committed).
8. **3MF, mesh units and mesh inertia (task 8, 2026-11-16).** Checked on two real Bambu Studio plates (3 and 2 objects, `unit="millimeter"`, Production-extension component files, build-item rotations with translations of 100 to 300 mm) with trimesh 5.2.1. `trimesh.load(..., force="scene")` reads the model unit into `scene.units`, composes component and build-item transforms into the scene graph (column-vector 4x4, translation in the file unit), and does **not** scale geometry or translations, so the importer applies `scale_to_si` to both. Every object was watertight with positive volume, and volumes agree with trimesh's to 1e-15 relative. A 3MF without a `unit` attribute defaults to millimetres. STL and OBJ carry no unit (importer defaults to 1.0 and records `file_unit = None`; the caller overrides). trimesh does not apply COLLADA's `<unit meter>`, so the importer reads it from the file (pycollada 0.9.3, BSD, added as a dependency for DAE). A placement with scale, shear or a mirror is baked into the vertices (winding flipped for a mirror). Mesh mass properties are the exact signed-tetrahedron sums over the welded mesh (`rigidforge.physics.mesh`), matching box analytics to 1e-10; only the tessellation error of item 4 remains. Fixtures are `rigidforge.testing.mesh_fixtures` (hand-built 3MF, STL, OBJ, DAE boxes).
9. **Leg pair placement and horn seating (2026-11-16, `tests/data/hexapod-leg`).** The coxa, femur and tibia frame pairs are each one printed part used twice, the second copy rotated 180° about the frame's x axis through the servo centre (a rigid copy, not a mirror). Boolean common volume between every pair of parts is ~0 within each pair (gaps: coxa 9 mm, femur 19 mm, tibia 0 mm, touching at the seam). With each horn's outer face 14.5 mm from the servo centre (11.5 mm body half-thickness plus 3 mm), every frame's horn face seats flush (zero overlap, zero gap). The tibia shaft (r 3.76 mm) overlaps each groove (r 3.58 mm) by 28.3 mm³, an intended press fit, so the interference check for task 19 must allow shaft-to-groove overlap. Placement is therefore verified by two automatic checks: pairwise Boolean common volume ~0, and flange-to-horn gap ~0.
10. **Leg assembly (2026-11-17, `rigidforge.testing.hexapod_leg`, `tests/physics/test_leg_assembly.py`).** The leg builds as base (coxa servo), coxa, femur and tibia links with a coxa yaw (axis z) and femur and tibia pitch joints (axis y, servo z = world y, servo rotation Rx(-90°)); femur axis at x = 43.5 mm, tibia axis 47.5 mm further, shaft tip 75 mm beyond. The ROBOTIS XL330-M288 table (18.0 g) has its origin on the horn's outer face with z toward the horn and y along the body, so x_cad = y_pdf, y_cad = -x_pdf, z_cad = z_pdf + 14.5 mm; the tensor is assumed to be about the CoM. The 18 g includes the drive horn (massless part) but not the idle horn, idle cap and idle horn screw (user, 2026-11-17), which have placeholder densities (plastic 1200, steel 7850 kg/m³) until weighed. The shaft is a hollow carbon-fibre tube, 1.15 g per 44.5 mm (user), an inertial override with tube inertia and an inferred 6 mm bore (3.0 mm inner radius). All placements from the layout notes pass the automatic checks: pairwise Boolean common volume is zero except the intended 28.3 mm³ shaft press fit in each tibia frame, and each frame's flange touches its horn face (distance below 1e-6 m). URDF and MJCF agree with an independent FK from the layout dimensions to 1e-12 at 50 random poses. Positive joint direction is the servo's +z (right-hand rule); not yet checked against a real servo.

## 7. Persistence (multi-session work)

**Layout.** A project directory with a JSON model file as the canonical store:

```
myrobot.rforge/
  project.json    # the model: links, joints, parts, materials, export targets
  assets/         # copied source STEP/meshes, imported xacro/URDF and their meshes
  cache/          # tessellation, BREP, collision hulls, mass props (regenerable, gitignored)
  workspace.json  # camera, panel layout, slider values (user-local, gitignored)
```

- Use pydantic `model_dump_json` with sorted keys, indentation and stable child order so diffs are readable in git. A zipped single-file `.rforge` bundle can be offered for sharing, but the directory is the working format. SQLite was rejected: it diffs badly and the model is small.
- **CAD assets are always copied** into `assets/`. Files are stored under their content hash or original name plus hash, so two imports of the same file are deduplicated.
- **Persist inputs, not derived data.** Persist part references, mass/density/material, manual inertia overrides, joint frames and limits, collision settings and export settings. Do not persist `TopoDS_Shape`, VTK actors, tessellations or computed inertia as authoritative values. Cache them under `cache/` keyed by a hash of geometry, scale, density, method and calc-code version, so a stale cache recomputes.
- **Identity.** Every link, joint and part has a stable UUID and is referenced by ID. Names are user-editable and exporters need unique names, so names are not keys.
- **Joint frames are numeric and authoritative**, in link coordinates (xyz + quaternion; RPY shown in the UI only). A snap reference (face and feature signature) is stored as a hint only, because B-Rep face indices are not stable across CAD re-exports.
- **Canonical units** are SI.
- **Simulator-specific data.** Core model plus namespaced extension blocks (`extensions.mjcf`, `.sdf`, `.usd`, `.urdf`), each its own pydantic model, for things like MJCF actuators and solver parameters, SDF friction and plugins, USD drive stiffness and physics-backend tuning. Per-target export config (output directory, mesh format, naming) is stored alongside.
- **Schema evolution.** `schema_version` in the file; a chain of dict-to-dict migrations runs before pydantic validation. Keep one fixture file per past version in tests. Newer-than-known files open read-only with a warning. Unknown extension keys round-trip rather than being dropped.
- **Save mechanics.** Atomic write (temp file, fsync, rename) with one rotating backup. Autosave to a recovery file beside the project and offer recovery after a crash. Undo is session-only (`QUndoStack` over model commands). A lock file (PID and host) warns about a second instance, and the on-disk hash is compared with the hash at load to catch outside edits.
- **Tests.** Round-trip property tests (save, load, equal); golden project files per schema version; exporting a loaded project gives byte-identical output to exporting the original in-memory model.

**Model shape (implemented 2026-11-16, `rigidforge.core.model`).** `RobotModel` holds flat, ordered lists of links, joints, parts and loop constraints, each with a UUID; references are by ID. A part points to its link (`None` while it is an unassigned import candidate), carries its source file, a placement in the link frame, an optional mirror plane in its own file coordinates, a mass source (`density` or `measured_mass`, a discriminated union) and an optional inertial override. A link may also carry an inertial override. Quaternions are scalar first (w, x, y, z). The pydantic layer checks structure only (types, vector lengths, unknown core fields rejected); semantic checks (single root, positive mass, unit quaternions, finite and ordered limits) belong to validation, so that a bad file loads and gets reported rather than failing to open. Extension blocks and the extension container allow extra keys so they round-trip.

**Validation (implemented 2026-11-16, `rigidforge.core.validation`).** `validate(model)` returns a `ValidationReport` of `Issue`s, each with a stable `IssueCode`, a severity (error blocks export, warning does not) and the offending item's UUID. Errors: duplicate IDs; empty names; duplicate names among links, among joints and among loop constraints (part names may repeat, since instances share a name); references to unknown links; tree structure (no links, self-joint, several parent joints for one link, no root, several roots, cycles found with Tarjan's SCC, unreachable links); revolute and prismatic joints without limits; non-finite or reversed limits; negative effort, velocity, damping or friction; zero or non-finite motion axes; non-finite poses and quaternions off unit length by more than 1e-6; non-positive or non-finite density, measured mass, override mass and `scale_to_si`; degenerate mirror planes; a loop constraint joining a link to itself. Warnings: position limits on fixed or continuous joints, and parts not assigned to a link. Inertial override tensors are also checked (M1 task 4): non-finite, not positive definite and triangle-inequality violations are errors (`inertia_not_finite`, `inertia_not_positive_definite`, `inertia_triangle_inequality`); a principal-moment ratio above 1e5 is a warning (`inertia_extreme_ratio`).

**Inertia checks and algebra (implemented 2026-11-16).** `rigidforge.core.inertia.check_inertia(mass, tensor)` is the one plausibility check, shared by validation and the physics code: mass > 0 and finite, tensor finite, symmetric (1e-9 relative to the largest component), positive definite (smallest eigenvalue > 0, so an ideal thin rod fails), and the triangle inequality on sorted principal moments with 1e-9 slack relative to the trace (an ideal flat plate sits exactly on the boundary and passes). It lives in `core/` because validation needs it and `core/` must not depend on `physics/`. `rigidforge.physics.inertia` holds `MassProperties` (mass, CoM, tensor about the CoM, in one frame), the analytic box/cylinder/sphere oracles (checked against OCCT `GProp` to 1e-6), `rotate_inertia` (R I Rᵀ), `parallel_axis` (I + m(|d|²E - d dᵀ)), `transformed` and `combine` (merge parts into one link about the combined CoM).

**STEP importer (implemented 2026-11-16, `rigidforge.importers.step`).** `read_step(path, scale_to_si=None)` reads through `STEPCAFControl_Reader` with name and colour modes and returns products (leaf part definitions, shape in metres, colour) and placed leaves (instance-name path from the root, 4x4 rigid transform in metres). Unit check: the declared unit comes from `STEPControl_Reader.FileUnits` (OCCT names such as `millimetre`, `metre`, `FOOT`; a file declaring none or several is rejected), and after transfer the XCAF document's `XCAFDoc_LengthUnit` attribute must read 1 m, which confirms `xstep.cascade.unit = M` took effect; the previous process-global value is restored afterwards. `PartSource.scale_to_si` is metres per file unit: the declared unit by default, or a caller override for a wrongly declared file, applied as a `gp_Trsf` scale to the B-Rep and to instance translations. Repeated products are shared, sibling instance names are made unique with `#2`, `#3`, and a non-rigid instance transform (scale, shear, mirror) is an error; mirrors are model-level operations (task 15). `candidate_parts` makes one unassigned `Part` per leaf, placed in the import root frame. `rigidforge.core.transforms` converts between `Pose` and 4x4 matrices (quaternion sign fixed to w >= 0 for stable files).

**B-Rep mass properties (implemented 2026-11-16, `rigidforge.physics.brep` and `rigidforge.physics.mass`).** `brep_unit_mass_properties(shape)` integrates a shape already in metres with `BRepGProp.VolumeProperties_s` in adaptive mode (`Eps = 1e-12`, `OnlyClosed = True`) and returns volume, CoM and the CoM tensor at 1 kg/m³ in the shape's own frame. OCCT's default fixed-order scheme is exact on analytic primitives but 2e-6 to 1e-5 off on the hexapod frames' B-spline surfaces (the spike's 4475.23 mm³ for the coxa frame is really 4475.244 mm³); `Eps` bounds the volume error and the inertia converges more slowly, so 1e-12 is used, giving tensors within about 1e-11 of a 1e-14 reference for about 20 ms per frame. A shape with no solids, open shells only, a reversed (negative-volume) solid or a volume below 1e-15 m³ is rejected. `part_mass_properties(part, unit)` applies the mass source (density: mass and tensor linear in density, CoM unchanged) or the part's inertial override (tensor rotated into the part frame by the override's orientation), checks the result with `check_inertia`, and records provenance: mass source (`density`, `measured_mass`, `override`), inertia method (`brep_exact`, `mesh`, `override`), the density applied, the volume, `CALC_VERSION`, and the override's source note. A measured mass (task 17) sets the effective density `measured / volume`, so the computed mass equals the scale reading and the tensor scales with it at fixed shape; the CoM stays geometric, and provenance records `measured_mass` with the effective density. `link_mass_properties` uses the link override, or moves each part into the link frame by its placement and merges about the combined CoM. Provenance is derived, not persisted, since the model already stores the inputs. Caching decision: the cache stores unit-density results keyed by `geometry_cache_key` (source sha256, assembly path, scale, mirror, method, calc version), not by density, because density is applied afterwards at negligible cost; this refines the section 7 rule above.

**Persistence (implemented 2026-11-16, `rigidforge.core.project`).** `save_project(model, dir)` writes `project.json` as canonical JSON (`model_dump(mode="json")`, sorted keys, two-space indent, UTF-8, trailing newline; non-finite floats are written as `NaN`/`Infinity` so a model with bad values still round-trips), atomically (temp file in the same directory, fsync, `os.replace`, directory fsync), after copying the previous file to `project.json.bak` (one rotating backup, gitignored). `load_project` reads the bytes, runs the dict-to-dict `MIGRATIONS` chain (keyed by the version migrated from) before pydantic validation, and returns the model plus `disk_hash` (sha256 of the bytes read), `read_only`, `warnings` and `migrated_from`. A file with a newer `schema_version` loads read-only with a warning if it still validates, and raises `UnsupportedSchemaError` if it does not (the model forbids unknown core fields, so only extension blocks are forward-compatible). Assets: `add_asset` copies a file to `assets/<sanitised stem>-<sha256[:12]><suffix>`, deduplicated by content (an existing copy with a matching hash is reused, a damaged one is rewritten); `asset_path` rejects names that escape `assets/`; `check_assets` reports missing, altered or unsafe assets; `remove_unused_assets` is left for callers to run. Lock file, autosave recovery and outside-edit prompts are M2 (GUI). The golden fixture for version 1 is `tests/data/golden/project-v1/project.json`; when the schema changes, keep it and add a new one per version.

**Exporters, CLI and layering (implemented 2026-11-16).** `rigidforge.exporters.urdf.export_urdf` and `rigidforge.exporters.mjcf.export_mjcf` are pure functions of the model plus precomputed link masses and mesh references; both validate first and refuse a model with errors, and write deterministic text (sorted attributes where order is free, fixed number formatting in `exporters/common.py`). URDF: lxml serializer, `rpy` with gimbal-lock handling, inertia in URDF order, effort and velocity required on revolute and prismatic joints, loop constraints dropped with a warning (URDF cannot express them). MJCF: bodies from the joint tree, `fullinertia` in MJCF order, hinge and slide joints with range, damping, friction and effort limits, position actuators from `extensions.mjcf`, loop constraints as site-based `connect`/`weld`, visual meshes in group 2 and collision meshes in group 3. Tests compile the MJCF in MuJoCo, load the URDF in yourdfpy, and compare FK between the two at random poses. The pipeline (`rigidforge.pipeline`, CLI `rforge build|export|validate` in `rigidforge.cli`) takes a JSON build spec (links, joints in the import frame, densities, MJCF actuators); the default is one link per leaf joined by fixed joints from the first. Masses are recomputed from the project's own copied assets, so an export from a reloaded project is byte-identical. Not yet done: visual and collision mesh files in the exports (the exporters accept `MeshRef`s, but B-Rep tessellation is not written yet) and mirrored parts (task 15). Layering is enforced three ways: the ruff banned-api rule, an AST backstop, and a fresh-interpreter test that imports the headless packages, pipeline and CLI with PySide6, VTK, pyvista and PyQt blocked. `types-lxml` (Apache-2.0) is a dev dependency so pyright strict can check the exporters; `pycollada` (BSD) is a runtime dependency for DAE.

**Instancing and mirror import (implemented 2026-11-16, `rigidforge.core.instancing`, `rigidforge.physics.mirror`).** A repeated part is a `Part` that shares `source` (asset, assembly path, scale) with another and differs only in `placement`: `rigid_copy` makes one (new UUID, no new geometry). `mirrored_copy` sets `Part.mirror`, a plane (point and normal) in the part file's own metre coordinates; a part that is already mirrored cannot be mirrored again. Mass properties bake the mirror into the geometry before integration: B-Rep through `gp_Trsf.SetMirror` and `BRepBuilderAPI_Transform(copy=True)`, mesh by reflecting vertices and reversing the winding; the placement is applied afterwards, in the link frame. Tests check volume, reflected CoM and `R I Rᵀ` on the hexapod frames for three planes (axis-aligned, offset and oblique), BRepCheck validity, and outward winding of mirrored meshes. `pipeline.compute_link_masses` now accepts mirrored parts; a degenerate plane is reported as a `BuildError`. The geometry cache key already covered the mirror.

**Re-import of CAD objects (required).** Proposed behaviour, to confirm:

1. Each part keeps an import record: source filename, sha256, the file's path on disk when last imported (as a hint), units, tessellation settings, and the part's path inside the STEP assembly (name plus index).
2. "Re-import" lets the user pick a new file for a part, or "Refresh" re-reads the original path. The new file is copied into `assets/` and the old copy is kept until the project is saved, so the action is undoable.
3. Matching sub-parts of an assembly to existing links: first by XCAF part name and path, then by geometric signature (volume and bounding box within tolerance), then ask the user for anything left over.
4. Preserved across re-import: link and joint identity, joint frames (numeric, in link coordinates), limits, mass/density/material, and manual overrides.
5. Recomputed: tessellation, B-Rep inertia and CoM, collision hulls (flagged as stale).
6. After matching, show a change report per part: volume, CoM shift and bounding-box change. Warn when a joint frame now lies outside the part's bounding box (likely the part moved in CAD). Snap hints are re-resolved where possible; where they fail, keep the numeric frame and mark the hint as unresolved.
7. Parts removed from the new file are shown as orphans for the user to delete or remap, and new parts are offered as additions. Nothing is deleted silently.
8. Detect stale sources on project open by comparing hashes against the original path, and offer a re-import without forcing it.
